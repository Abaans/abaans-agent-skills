# Example change map and review cases

Use fictional or disposable documents for testing.

## Requested update

“Apply the revised eligibility paragraph to the specified shared Product Overview. Keep the title, all revision-history rows and the diagram below that paragraph.”

| Destination | Requested edit | Protected content | Completion evidence |
|---|---|---|---|
| Eligibility paragraph | Replace only the specified sentence | Adjacent diagram and caption | Saved text visible after canonical cloud reopen |
| Revision table | Add a supported new revision if requested | Every earlier row and approval field | Prior rows unchanged; new row occurs once |

A valid report names the changed range, preserved items and cloud persistence state. It does not claim colleague-device refresh.

## Reviewer checks

- A collaborator changes the same paragraph after inspection: re-read and reconcile or stop that range; do not paste the old replacement blindly.
- An available connector only replaces file binaries: provide a change map and report the editing capability gap.
- Word says saved but the canonical cloud item cannot be reopened: report persistence unverified.
- Revised prose surrounds an embedded image: edit the separate ranges around the image.
- A draft contains a generic title: preserve the meaningful live title unless the user requested a title change.

These are manual behavioral review cases. They do not automate or certify a live Word/OneDrive session.
